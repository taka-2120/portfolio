Swift can run on Android. Not a stripped-down version — actual Swift code, with third-party packages like Alamofire. This post documents the setup process for getting Swift logic running inside an Android app using [swift-java](https://github.com/swiftlang/swift-java).

## What this project does

The repository has two parts:

- `logic-lib` — a Swift package that exports two classes: `Encoder` (UTF-8 encoding) and `APIHandler` (HTTP GET via Alamofire)
- `swift-android-app` — a Jetpack Compose Android app that calls those Swift classes through the JVM bridge generated by swift-java

On the Kotlin side, `yutakahashi.LogicLib.APIHandler` and `yutakahashi.LogicLib.Encoder` are imported like regular JVM classes. The bridge is transparent once set up.

## Requirements

- macOS (the Swiftly installer ships as a `.pkg`)
- JDK 25+ (tested with Amazon Corretto 25.0.1 via sdkman)
- Swiftly (Swift toolchain manager)
- Swift 6.3 or later
- Swift SDK for Android (official artifact bundle from swift.org)
- Android Studio

## 1. Install JDK via sdkman

```bash
curl -s "https://get.sdkman.io" | bash
sdk install java 25.0.1-amzn --use
export JAVA_HOME="${HOME}/.sdkman/candidates/java/current"
```

sdkman handles multiple JDK versions without manually moving files around. The `JAVA_HOME` export needs to be in your shell profile to survive across sessions.

## 2. Install Swift via Swiftly

Swiftly is Swift's official toolchain manager — the rustup equivalent.

```bash
curl -L https://download.swift.org/swiftly/darwin/swiftly.pkg > swiftly.pkg
installer -pkg swiftly.pkg -target CurrentUserHomeDirectory
~/.swiftly/bin/swiftly init
```

Then install Swift 6.3+:

```bash
swiftly install latest
swiftly use latest
```

## 3. Install the Swift SDK for Android

The SDK is distributed as an artifact bundle. This is the Swift 6.3.1 version:

```bash
swift sdk install \
  https://download.swift.org/swift-6.3.1-release/android-sdk/swift-6.3.1-RELEASE/swift-6.3.1-RELEASE_android.artifactbundle.tar.gz \
  --checksum 8193a4e96538635131a154736c8896fba0e5a1c30e065524f00ed78719bac35a
```

The `--checksum` flag verifies the download against a known SHA-256.

## 4. Build and publish logic-lib

`logic-lib` is the Swift package containing the actual logic. The `JExtractSwiftPlugin` from swift-java (declared in `Package.swift`) generates the JVM bridge code at build time.

```bash
cd logic-lib
swift package resolve
./.build/checkouts/swift-java/gradlew \
  --project-dir .build/checkouts/swift-java \
  :SwiftKitCore:publishToMavenLocal
```

`publishToMavenLocal` pushes SwiftKitCore — the JVM glue runtime — into your local Maven cache so Android Studio can resolve it as a dependency.

## 5. Run in Android Studio

Open the root of the repository in Android Studio and press Run or Debug. The app has two demo sections:

- **Swift Encoder** — types a string, Swift converts it to UTF-8 hex bytes
- **Swift APIHandler** — Alamofire fetches `https://httpbin.org/get` and the raw JSON response appears in the app

## How the bridge works

swift-java's `JExtractSwiftPlugin` reads your Swift source at build time and generates `.java` wrapper classes that proxy calls to the compiled Swift `.so` via JNI. On the Kotlin side, `SwiftArena` manages the lifetime of Swift objects — analogous to ARC, but explicit, since the JVM doesn't know when to release Swift heap memory.

```kotlin
SwiftArena.ofConfined().use { arena ->
    val encoder = Encoder.init(arena)
    val data = encoder.encode(inputText, arena)
}
```

Swift `async throws` functions are exported as `CompletableFuture` on the JVM side. The Kotlin caller calls `.get()` on the future to block and retrieve the result.
