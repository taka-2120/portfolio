Swift can run on Android. Not a stripped-down version — actual Swift code, with third-party packages like Alamofire. This post documents the setup process for getting Swift logic running inside an Android app using [swift-java](https://github.com/swiftlang/swift-java).

## What this project does

The repository is split into two parts. `logic-lib` is a Swift package that exports two classes: `Encoder`, which converts a string to UTF-8 bytes, and `APIHandler`, which makes HTTP GET requests using Alamofire. `swift-android-app` is a Jetpack Compose Android app that calls those Swift classes through a JVM bridge generated by swift-java.

What makes this interesting is that on the Kotlin side, `yutakahashi.LogicLib.APIHandler` and `yutakahashi.LogicLib.Encoder` are imported like any regular JVM class — the bridge is transparent once the setup is done.

## Requirements

Before starting, you'll need a few things in place. The Swiftly installer ships as a `.pkg`, so macOS is required. For the JDK, version 25 or later is needed — I used Amazon Corretto 25.0.1 installed via sdkman. You'll also need Swiftly (Swift's toolchain manager), Swift 6.3 or later, the official Swift SDK for Android artifact bundle from swift.org, and Android Studio.

## 1. Install JDK via sdkman

sdkman is a version manager for JDK distributions. It keeps things clean — no manually moving files around, and switching between versions is just one command.

```bash
curl -s "https://get.sdkman.io" | bash
sdk install java 25.0.1-amzn --use
export JAVA_HOME="${HOME}/.sdkman/candidates/java/current"
```

One thing to watch: the `JAVA_HOME` export won't survive a new terminal session unless you add it to your shell profile (`.zshrc`, `.bashrc`, etc.).

## 2. Install Swift via Swiftly

Swiftly is Swift's official toolchain manager, roughly equivalent to rustup for Rust. It handles installing and switching between Swift versions without touching the system Swift.

```bash
curl -L https://download.swift.org/swiftly/darwin/swiftly.pkg > swiftly.pkg
installer -pkg swiftly.pkg -target CurrentUserHomeDirectory
~/.swiftly/bin/swiftly init
```

After that, installing Swift 6.3 is straightforward:

```bash
swiftly install latest
swiftly use latest
```

## 3. Install the Swift SDK for Android

The Swift SDK for Android is distributed as an artifact bundle directly from swift.org. The command below installs the Swift 6.3.1 version:

```bash
swift sdk install \
  https://download.swift.org/swift-6.3.1-release/android-sdk/swift-6.3.1-RELEASE/swift-6.3.1-RELEASE_android.artifactbundle.tar.gz \
  --checksum 8193a4e96538635131a154736c8896fba0e5a1c30e065524f00ed78719bac35a
```

The `--checksum` flag verifies the download against a known SHA-256, so you can be sure the bundle hasn't been tampered with or corrupted.

## 4. Build and publish logic-lib

`logic-lib` is where the actual Swift code lives. Its `Package.swift` includes the `JExtractSwiftPlugin` from swift-java, which automatically generates JVM wrapper classes from the Swift source at build time. Before Android Studio can pick up the runtime it depends on, you need to publish it to your local Maven cache:

```bash
cd logic-lib
swift package resolve
./.build/checkouts/swift-java/gradlew \
  --project-dir .build/checkouts/swift-java \
  :SwiftKitCore:publishToMavenLocal
```

The `publishToMavenLocal` task puts SwiftKitCore — the JVM glue runtime — into `~/.m2`, which is where Android Studio will look for it as a dependency.

## 5. Run in Android Studio

Open the root of the repository in Android Studio and press Run or Debug. The app has two demo sections. In the first, you type a string and Swift converts it to UTF-8 hex bytes using the `Encoder` class. In the second, a button triggers Alamofire to fetch `https://httpbin.org/get` and the raw JSON response appears in the app — all the HTTP work happening inside Swift, called from Kotlin.

## How the bridge works

The `JExtractSwiftPlugin` reads your Swift source at build time and generates `.java` wrapper classes that proxy calls to the compiled Swift `.so` via JNI. On the Kotlin side, `SwiftArena` manages the lifetime of Swift objects. Since the JVM has no way to know when to release Swift heap memory, you have to be explicit about it — similar in spirit to ARC, but manual:

```kotlin
SwiftArena.ofConfined().use { arena ->
    val encoder = Encoder.init(arena)
    val data = encoder.encode(inputText, arena)
}
```

When the `use` block exits, the arena is closed and the Swift objects are released. For async Swift functions — those marked `async throws` — swift-java exports them as `CompletableFuture` on the JVM side, and the Kotlin caller uses `.get()` to block and retrieve the result.
